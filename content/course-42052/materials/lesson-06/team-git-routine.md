# שגרת git של הצוות

<!-- דף אחד. לפני כל שינוי, ובכל מחשב. -->

## 1. pull – מושכים קודם

`git pull` – מקבלים את מה שחברי הצוות דחפו מאז הפעם הקודמת.

## 2. change – שינוי קטן אחד

בקשה לסוכן: תוכנית קודם, שינוי אחד, הצגת ה-diff. לא נוגעים ב-`SPEC.md` בלי החלטה של הצוות.

## 3. run – מריצים

מריצים את מסלול הליבה לפי `README.md`, ומשווים לתשובה הצפויה.

## 4. commit – שומרים

`git add` ואז `git commit -m "מה השתנה ולמה"`.

## 5. push – משתפים

שוב `git pull`, מריצים אם משהו נכנס, ורק אז `git push`.

## כשמשהו לא מסתדר

- **קונפליקט** (שורות `<<<<<<<`, `=======`, `>>>>>>>` בקובץ): עוצרים. קוראים את שתי הגרסאות, מחליטים יחד, בודקים את ה-diff, מריצים – ורק אז commit ו-push.
- **אף פעם** `git push --force` על הענף המשותף (הענף הראשי, בדרך כלל `main`, שעליו כל הצוות עובד).
- **אף פעם** סיסמה, מפתח API או טוקן בקובץ, ב-commit או בשיחה עם הסוכן.
